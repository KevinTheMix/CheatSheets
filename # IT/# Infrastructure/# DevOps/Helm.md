# Helm

Package manager & template engine for Kubernetes, using parameterized Go templates (charts) associated with values to render K8s YAML manifests (helping reduce their numbers).

## Quick Tips

* Similar alternative = Kustomize (template-free overlays/patches on plain YAML)

## Glossary

* **Chart** = package, ie whole directory bundling everything needed to deploy an application on K8s (templates, default values, metadata, dependencies)
* **Release** = a deployed instance of a chart in a cluster, with its own name & revision history

## Environment

### File Structure

* _.helmignore_ = patterns of files to exclude when packaging the chart (like _.gitignore_)
* _Chart.lock_ = locked versions of dependencies, generated by `helm dependency update`
* _Chart.yaml_ = chart metadata (`apiVersion`, `name`, `version` of the chart, `appVersion` of the deployed app, `description`, `dependencies`)
* _charts_ = folder containing dependency (sub)charts, either vendored or downloaded from `Chart.yaml` dependencies
* _crds_ = folder containing Custom Resource Definitions, installed before templates & never templated/upgraded/deleted by Helm
* _README.md_ = human-readable chart documentation (eg shown on Artifact Hub)
* _templates_ = folder containing Go templates rendered with values into K8s manifests
  * _\_helpers.tpl_ = standard file holding reusable named template snippets (defined with `{{- define "<chart>.name" -}}` and called with `include`/`template`, eg chart name/fullname, common labels, selector labels), which isn't rendered as a manifest itself since files starting with `_` are skipped
  * _{resource}.yaml_ = one manifest template per K8s resource (eg _deployment.yaml_, _service.yaml_, _ingress.yaml_, _configmap.yaml_)
  * _NOTES.txt_ = templated usage notes printed after `helm install`/`upgrade`
  * _tests_ = folder containing test pods (annotated `helm.sh/hook: test`) run by `helm test`
* _values.schema.json_ = optional JSON Schema validating values on install/upgrade/lint
* _values.yaml_ = default configuration values, accessible in templates via `.Values` & overridable via `-f <file>` or `--set`

### CLI

* `helm upgrade` = update an existing release with new changes from a chart
  * `--debug` = enable verbose output (eg shows rendered manifests) for troubleshooting
  * `--force-replace` = replace existing deployment configuration (eg manually added environment variables) without warning/error
  * `--rollback-on-failure` = automatically roll back to previous release if upgrade fails
  * `--set env=dev` = override a chart value from CLI (here sets `env` to `dev`) instead of editing `values.yaml`
